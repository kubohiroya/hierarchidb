# BaseMap Plugin テスト仕様書

## 概要
本ドキュメントは、basemap-pluginのユーザシナリオに基づいたテスト仕様を定義します。地図ベースノードの作成・編集における段階的な設定と、マップレイヤーのバッチ処理を包括的にテストします。

## ユーザシナリオ

### シナリオ1: ベースマップノードの段階的作成
**目的**: ユーザが新しいベースマップノードを作成し、段階的に地図設定を構築していくプロセス

1. **開始**: ベースマップノード作成を開始
2. **基本設定**: マップタイプ、初期座標、ズームレベルを設定
3. **レイヤー追加**: タイルレイヤー、オーバーレイを追加
4. **マーカー配置**: POIマーカーを配置
5. **中断・再開**: 作業を中断し、後で再開
6. **完了**: 全ての設定を確認し、ノード作成を完了

### シナリオ2: 既存ベースマップノードの編集
**目的**: 既存のベースマップノードを編集し、レイヤーやスタイルを変更

1. **編集開始**: 既存ベースマップノードの編集モードに入る
2. **レイヤー管理**: レイヤーの追加・削除・順序変更
3. **スタイル変更**: マップスタイルやテーマを変更
4. **プレビュー**: 変更内容を地図上でプレビュー
5. **破棄・やり直し**: 変更を破棄して再編集
6. **保存**: 変更を確定して保存

### シナリオ3: マップデータのバッチ処理
**目的**: 複数のマップ要素に対する一括操作

1. **バッチ開始**: 複数マーカーやレイヤーを選択してバッチ処理開始
2. **一括スタイル変更**: マーカーアイコンやレイヤー透明度を一括変更
3. **クラスタリング**: マーカーの自動クラスタリング
4. **進捗確認**: 処理の進捗状況を確認
5. **中断・再開**: 処理を中断し、後で再開
6. **完了・破棄**: 処理を完了または破棄

## テストケース

### TC1: ベースマップノード作成フロー

#### TC1.1: 基本的な作成フロー
- **前提条件**: データベース初期化済み
- **手順**:
  1. WorkingCopyを作成
  2. マップタイプ（OpenStreetMap）を選択
  3. 初期表示位置（緯度: 35.6762, 経度: 139.6503）を設定
  4. ズームレベル（13）を設定
  5. WorkingCopyをコミット
- **期待結果**: 
  - CoreDBにベースマップノードが保存される
  - 地図設定が正しく適用される

#### TC1.2: レイヤーの段階的追加
- **前提条件**: WorkingCopy作成済み
- **手順**:
  1. ベースタイルレイヤーを設定
  2. 地形レイヤーを追加
  3. 交通情報オーバーレイを追加
  4. カスタムタイルレイヤーを追加
  5. レイヤー順序を調整
  6. コミット
- **期待結果**:
  - 全レイヤーが正しい順序で追加される
  - 各レイヤーの設定が保持される

#### TC1.3: マーカーとポリゴンの配置
- **前提条件**: WorkingCopy作成済み
- **手順**:
  1. POIマーカーを複数配置
  2. カスタムアイコンを設定
  3. エリアポリゴンを描画
  4. ポリライン（経路）を追加
  5. 各要素にポップアップを設定
  6. コミット
- **期待結果**:
  - 全要素が正しい位置に配置される
  - ポップアップ情報が関連付けられる

#### TC1.4: 作成中の中断と再開
- **前提条件**: WorkingCopy作成済み
- **手順**:
  1. 基本設定とレイヤーを追加
  2. セッションを中断
  3. WorkingCopyを再読み込み
  4. マーカーを追加
  5. コミット
- **期待結果**:
  - 中断前の設定が保持される
  - 再開後の追加が正しく保存される

### TC2: ベースマップノード編集フロー

#### TC2.1: レイヤー管理
- **前提条件**: 既存ベースマップノード存在
- **手順**:
  1. 編集用WorkingCopyを作成
  2. 既存レイヤーを削除
  3. 新しいレイヤーを追加
  4. レイヤー順序を変更
  5. レイヤー透明度を調整
  6. コミット
- **期待結果**:
  - レイヤー変更が正しく適用される
  - 表示順序が保持される

#### TC2.2: マップスタイル変更
- **前提条件**: 既存ベースマップノード存在
- **手順**:
  1. 編集用WorkingCopyを作成
  2. マップスタイルをダークテーマに変更
  3. カラーパレットを調整
  4. ラベル表示設定を変更
  5. プレビューで確認
  6. コミット
- **期待結果**:
  - スタイル変更が適用される
  - カスタム設定が保存される

#### TC2.3: ビューポート設定の更新
- **前提条件**: 既存ベースマップノード存在
- **手順**:
  1. 編集用WorkingCopyを作成
  2. デフォルトズームレベルを変更
  3. 表示範囲制限を設定
  4. 最小/最大ズームを設定
  5. コミット
- **期待結果**:
  - ビューポート設定が更新される
  - 制限が正しく機能する

### TC3: バッチ処理フロー

#### TC3.1: マーカーの一括スタイル変更
- **前提条件**: 複数のマーカーを持つマップノード存在
- **手順**:
  1. バッチ処理を開始
  2. 対象マーカーを選択
  3. アイコンスタイルを一括変更
  4. サイズと色を統一
  5. バッチを実行
- **期待結果**:
  - 全選択マーカーのスタイルが更新される
  - 個別の属性は保持される

#### TC3.2: 自動クラスタリング
- **前提条件**: 大量のマーカーを持つマップノード存在
- **手順**:
  1. バッチ処理を開始
  2. クラスタリング設定を定義
  3. 距離閾値を設定
  4. クラスタースタイルを設定
  5. バッチを実行
- **期待結果**:
  - マーカーが適切にクラスタリングされる
  - ズームレベルに応じて動的に変化する

#### TC3.3: レイヤーの一括操作
- **前提条件**: 複数レイヤーを持つマップノード群存在
- **手順**:
  1. バッチ処理を開始
  2. 共通レイヤーを追加
  3. 不要レイヤーを一括削除
  4. 透明度を統一
  5. バッチを実行
- **期待結果**:
  - 全対象ノードのレイヤーが更新される
  - 一貫性のある設定が適用される

#### TC3.4: タイルキャッシュ管理
- **前提条件**: タイルレイヤーを持つマップノード群存在
- **手順**:
  1. バッチ処理を開始
  2. キャッシュ対象エリアを選択
  3. ズームレベル範囲を指定
  4. プリフェッチを実行
  5. 進捗を監視
- **期待結果**:
  - タイルが効率的にキャッシュされる
  - オフライン表示が可能になる

#### TC3.5: バッチ処理の進捗管理と中断
- **前提条件**: 大量の要素を持つマップノード存在
- **手順**:
  1. バッチ処理を開始
  2. 処理進捗を監視
  3. 50%時点で中断
  4. 状態を確認
  5. 処理を再開または破棄
- **期待結果**:
  - 進捗が正確に報告される
  - 中断・再開が正しく機能する

## マップ要素別テスト

- ベクタータイル（MVT）
- WMSレイヤー
- カスタムタイルサーバー

### オーバーレイ要素
- マーカー（単一/クラスター）
- ポリゴン（単純/穴あき）
- ポリライン（単純/マルチ）
- サークル/楕円
- ヒートマップ

### インタラクション
- クリック/タップイベント
- ドラッグ&ドロップ
- ズーム/パン制御
- ポップアップ/ツールチップ

## テスト環境

### 必要なモック/スタブ
- fake-indexeddb: IndexedDBのメモリ実装
- タイルサーバーのモック
- 地図レンダリングライブラリのモック
- Worker環境のモック

### テストデータ
- サンプルタイルセット
- マーカーデータセット
- ジオメトリサンプル
- スタイルテンプレート

## パフォーマンス基準
- マップ初期化: 500ms以下
- レイヤー追加: 100ms/レイヤー以下
- マーカー描画: 1000件/秒以上
- タイル読み込み: 50ms/タイル以下

## 成功条件
- 全テストケースが成功
- カバレッジ80%以上
- パフォーマンス基準を満たす
- メモリリークがない

## リスクと対策
- **リスク**: タイルサーバーの可用性
- **対策**: ローカルタイルキャッシュとフォールバック

- **リスク**: 大量マーカーのパフォーマンス
- **対策**: 自動クラスタリングと仮想スクロール
