# Shape Plugin テスト仕様書

## 概要
本ドキュメントは、shape-pluginのユーザシナリオに基づいたテスト仕様を定義します。図形ノードの作成・編集における段階的な属性設定と、バッチ処理による一括変更を包括的にテストします。

## ユーザシナリオ

### シナリオ1: 図形ノードの段階的作成
**目的**: ユーザが新しい図形ノードを作成し、段階的に形状やスタイルを設定していくプロセス

1. **開始**: 図形ノード作成を開始
2. **基本形状選択**: 図形タイプ（矩形、円、多角形等）を選択
3. **寸法設定**: サイズ、位置、回転角度を設定
4. **スタイル設定**: 色、線の太さ、透明度を設定
5. **中断・再開**: 作業を中断し、後で再開
6. **完了**: 全ての属性を確認し、ノード作成を完了

### シナリオ2: 既存図形ノードの編集
**目的**: 既存の図形ノードを編集し、形状やスタイルを変更

1. **編集開始**: 既存図形ノードの編集モードに入る
2. **形状変更**: 図形タイプや寸法を変更
3. **スタイル変更**: 配色やエフェクトを変更
4. **プレビュー**: 変更内容を視覚的にプレビュー
5. **破棄・やり直し**: 変更を破棄して再編集
6. **保存**: 変更を確定して保存

### シナリオ3: 図形ノードのバッチ処理
**目的**: 複数の図形ノードに対する一括スタイル変更

1. **バッチ開始**: 複数図形ノードを選択してバッチ処理開始
2. **変換定義**: スタイルや変形の一括変更を定義
3. **進捗確認**: 処理の進捗状況を確認
4. **プレビュー**: バッチ処理結果のプレビュー
5. **中断・再開**: 処理を中断し、後で再開
6. **完了・破棄**: 処理を完了または破棄

## テストケース

### TC1: 図形ノード作成フロー

#### TC1.1: 基本的な作成フロー
- **前提条件**: データベース初期化済み
- **手順**:
  1. WorkingCopyを作成
  2. 図形タイプを選択（矩形）
  3. 寸法を設定（幅: 100, 高さ: 50）
  4. スタイルを設定（背景色: #FF0000, 枠線: 2px）
  5. WorkingCopyをコミット
- **期待結果**: 
  - CoreDBに図形ノードが保存される
  - 全ての属性が正しく設定される

#### TC1.2: 複雑な図形の段階的作成
- **前提条件**: WorkingCopy作成済み
- **手順**:
  1. 多角形タイプを選択
  2. 頂点座標を順次追加
  3. 各頂点の位置を調整
  4. グラデーション設定
  5. 影効果を追加
  6. コミット
- **期待結果**:
  - 複雑な図形が正しく構築される
  - 全てのスタイル属性が適用される

#### TC1.3: 作成中の中断と再開
- **前提条件**: WorkingCopy作成済み
- **手順**:
  1. 図形タイプと基本寸法を設定
  2. セッションを中断
  3. WorkingCopyを再読み込み
  4. スタイル設定を追加
  5. コミット
- **期待結果**:
  - 中断前の設定が保持される
  - 再開後の変更が正しく適用される

#### TC1.4: 作成の破棄
- **前提条件**: WorkingCopy作成済み、属性設定済み
- **手順**:
  1. 図形属性を完全に設定
  2. WorkingCopyを破棄
- **期待結果**:
  - EphemeralDBからWorkingCopyが削除される
  - CoreDBに変更が反映されない

### TC2: 図形ノード編集フロー

#### TC2.1: 形状変更
- **前提条件**: 既存矩形ノード存在
- **手順**:
  1. 編集用WorkingCopyを作成
  2. 図形タイプを円に変更
  3. 半径を設定
  4. コミット
- **期待結果**:
  - 図形タイプが変更される
  - 関連属性が適切に更新される

#### TC2.2: スタイル変更とプレビュー
- **前提条件**: 既存図形ノード存在
- **手順**:
  1. 編集用WorkingCopyを作成
  2. 色を変更
  3. プレビューで確認
  4. 透明度を調整
  5. 再度プレビュー
  6. コミット
- **期待結果**:
  - プレビューが正確に表示される
  - 最終的なスタイルが正しく保存される

#### TC2.3: 変形操作の適用
- **前提条件**: 既存図形ノード存在
- **手順**:
  1. 編集用WorkingCopyを作成
  2. 回転角度を設定（45度）
  3. スケールを変更（1.5倍）
  4. 位置を移動
  5. コミット
- **期待結果**:
  - 全ての変形が正しく適用される
  - 変形の順序が保持される

### TC3: バッチ処理フロー

#### TC3.1: スタイル一括変更
- **前提条件**: 複数の図形ノード存在（異なるタイプ）
- **手順**:
  1. バッチ処理を開始
  2. 対象ノードを選択
  3. 共通スタイル（色、線幅）を定義
  4. バッチを実行
- **期待結果**:
  - 全選択ノードのスタイルが更新される
  - 図形タイプ固有の属性は保持される

#### TC3.2: 変形の一括適用
- **前提条件**: 複数の図形ノード存在
- **手順**:
  1. バッチ処理を開始
  2. スケール変更（0.5倍）を定義
  3. 回転（90度）を追加
  4. バッチを実行
- **期待結果**:
  - 全ノードに変形が適用される
  - 相対的な位置関係が保持される

#### TC3.3: 条件付きバッチ処理
- **前提条件**: 様々な属性を持つ図形ノード群
- **手順**:
  1. バッチ処理を開始
  2. フィルタ条件を設定（赤色の図形のみ）
  3. 青色への変更を定義
  4. プレビューで対象を確認
  5. バッチを実行
- **期待結果**:
  - 条件に合致するノードのみが変更される
  - 他のノードは影響を受けない

#### TC3.4: バッチ処理の進捗管理
- **前提条件**: 大量の図形ノード存在（100個以上）
- **手順**:
  1. バッチ処理を開始
  2. 処理中に進捗を監視
  3. 進捗率を確認
  4. 完了を待つ
- **期待結果**:
  - 進捗が正確に報告される
  - パフォーマンスが許容範囲内

#### TC3.5: バッチ処理の中断・再開・破棄
- **前提条件**: バッチ処理実行中
- **手順**:
  1. バッチ処理を開始
  2. 30%時点で中断
  3. 状態を確認
  4. 処理を再開
  5. 完了前に破棄を選択
- **期待結果**:
  - 中断位置が記録される
  - 再開時に重複処理されない
  - 破棄時に全変更がロールバックされる

## 図形タイプ別テスト

### 矩形（Rectangle）
- 幅、高さの設定
- 角丸の設定
- アスペクト比の保持

### 円（Circle）
- 半径の設定
- 楕円への変形
- 中心点の管理

### 多角形（Polygon）
- 頂点数の変更
- 頂点座標の編集
- 正多角形への変換

### パス（Path）
- ベジェ曲線の制御
- パスの結合・分割
- SVGパスデータのインポート/エクスポート

## テスト環境

### 必要なモック/スタブ
- fake-indexeddb: IndexedDBのメモリ実装
- Canvas APIのモック（図形レンダリング用）
- Worker環境のモック

### テストデータ
- 各図形タイプのサンプルデータ
- スタイルプリセット
- 変形マトリックスのテストケース

## パフォーマンス基準
- 単一ノード作成: 100ms以下
- バッチ処理: 1000件/秒以上
- プレビュー生成: 50ms以下

## 成功条件
- 全テストケースが成功
- カバレッジ80%以上
- パフォーマンス基準を満たす

## リスクと対策
- **リスク**: 図形タイプごとの属性管理の複雑さ
- **対策**: タイプ別のバリデーションとテスト
