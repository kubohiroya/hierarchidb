# StylerCSVApiDriver テストケース洗い出し

## 開発言語・フレームワーク

- **プログラミング言語**: TypeScript
  - **言語選択の理由**: HierarchiDBプロジェクトの標準言語、型安全性の確保
  - **テストに適した機能**: 型チェック、インターフェース実装確認、branded typeサポート
- **テストフレームワーク**: Vitest
  - **フレームワーク選択の理由**: 既存プロジェクトで使用、高速実行、ESModulesサポート
  - **テスト実行環境**: Node.js環境、fake-indexeddb使用でブラウザAPI模擬
- 🟢 既存のテスト設定と一致、実装済みテストファイルから確認済み

## テストケースの分類

### 1. 正常系テストケース（基本的な動作）

#### **CSV ファイルアップロード機能**

- **テスト名**: 標準的なCSVファイルの正常アップロード処理
  - **何をテストするか**: 基本的なCSVファイル（カンマ区切り、ヘッダーあり）の解析とメタデータ生成
  - **期待される動作**: ファイル内容の解析、列情報の抽出、メタデータオブジェクト生成
- **入力値**: `name,age,city\nJohn,30,New York\nJane,25,Los Angeles` (CSV形式)
  - **入力データの意味**: 3列3行の典型的なCSV構造、文字列・数値・文字列の混合型
- **期待される結果**: `{ filename: 'test.csv', totalRows: 2, columns: [3個], referenceCount: 0 }`
  - **期待結果の理由**: ヘッダー行を除く実データ行数、各列のメタデータ、初期状態での参照カウント
- **テストの目的**: 基本的なCSV解析機能の確認
  - **確認ポイント**: 列数の正確な検出、行数の正確なカウント、型推定の実行
- 🟢 既存テストファイルで実装済み、仕様書と完全一致

- **テスト名**: TSVファイル（タブ区切り）の正常処理
  - **何をテストするか**: タブ区切りファイルの自動検出と解析処理
  - **期待される動作**: デリミター自動判定、TSV特有のデータ構造の正確な解析
- **入力値**: `name\tage\tcity\nJohn\t30\tNew York` (TSV形式)
  - **入力データの意味**: タブ区切り形式のファイル、空白を含む値の処理確認
- **期待される結果**: 正常なメタデータ生成、3列2行の認識
  - **期待結果の理由**: タブ区切りでも標準CSV同様の処理が期待される
- **テストの目的**: 複数デリミター対応の確認
  - **確認ポイント**: タブ文字の正確な認識、空白値の適切な処理
- 🟢 既存テストファイルで実装済み、デリミター対応仕様と一致

- **テスト名**: 列の型自動判定機能
  - **何をテストするか**: 各列のデータ型（string/number/boolean）の自動推定
  - **期待される動作**: 値の分析による適切な型分類、型情報のメタデータ反映
- **入力値**: `name,age,is_active\nJohn,30,true\nJane,25,false`
  - **入力データの意味**: 文字列・数値・真偽値の混合データ、型推定テスト用
- **期待される結果**: `columns[0].type='string'`, `columns[1].type='number'`, `columns[2].type='boolean'`
  - **期待結果の理由**: データ内容から推定される最適な型分類
- **テストの目的**: データ型推定アルゴリズムの精度確認
  - **確認ポイント**: 各データ型の正確な識別、混合データでの型判定
- 🟢 既存テストファイルで実装済み、型推定仕様と一致

#### **フィルタリング機能**

  - **期待される動作**: 指定列の値が条件と完全一致する行のみを抽出
- **入力値**: `city='New York'` フィルター条件

- **テストの目的**: 基本フィルタ機能の確認
  - **確認ポイント**: 条件一致判定の正確性、結果行数の一致
- 🟢 既存テストファイルで実装済み、フィルタリング仕様と一致

  - **期待される動作**: 指定文字列を含む行の抽出、大文字小文字考慮
- **入力値**: `name contains 'a'` フィルター条件
  - **入力データの意味**: 文字列内の部分一致検索、柔軟な検索条件
- **期待される結果**: 'a'を含む名前の3名抽出 (Jane, Alice, Charlie)
  - **期待結果の理由**: 文字列内に指定文字を含む行の正確な抽出
- **テストの目的**: 部分一致検索の動作確認
  - **確認ポイント**: 大文字小文字の処理、部分一致の正確性
- 🟢 既存テストファイルで実装済み、部分一致検索仕様と一致

- **テスト名**: 複数条件のANDロジック処理
  - **何をテストするか**: 複数フィルタ条件の同時適用（論理積）
  - **期待される動作**: 全ての条件を満たす行のみを抽出する絞り込み処理
- **入力値**: `city='New York' AND age > 25`
  - **入力データの意味**: 地域と年齢の複合条件、現実的なフィルタシナリオ
- **期待される結果**: New Yorkかつ25歳超の2名抽出 (John 30, Alice 28)

  - **確認ポイント**: AND論理の正確な実装、条件組み合わせの動作
- 🟢 既存テストファイルで実装済み、複合条件仕様と一致

#### **参照管理機能**

- **テスト名**: テーブル参照の追加と削除
  - **何をテストするか**: プラグインからのテーブル参照登録・解除処理
  - **期待される動作**: 参照カウントの正確な増減、参照プラグインリストの更新

  - **確認ポイント**: カウント増減の正確性、プラグインリストの管理
- 🟢 既存テストファイルで実装済み、参照管理仕様と一致

  - **期待される動作**: 参照がなくなったテーブルデータの完全削除

### 2. 異常系テストケース（エラーハンドリング）

#### **ファイル形式エラー**

- **テスト名**: 空ファイルのアップロード処理
  - **エラーケースの概要**: データが全く含まれていないファイルの処理
  - **エラー処理の重要性**: 不正なファイルでのシステムクラッシュ防止
- **入力値**: `''` (空文字列ファイル)
  - **不正な理由**: CSVとして解析すべきデータが存在しない
  - **実際の発生シナリオ**: ユーザーが誤って空ファイルをアップロード
- **期待される結果**: `throw new Error('No columns found')`
  - **エラーメッセージの内容**: ユーザーに分かりやすい具体的なエラー内容
  - **システムの安全性**: 処理を安全に中断し、システム状態を保持
- **テストの目的**: 不正ファイルでのエラーハンドリング確認
  - **品質保証の観点**: ユーザビリティとシステム安定性の両立
- 🟢 既存テストファイルで実装済み、エラーハンドリング仕様と一致

- **テスト名**: ヘッダーのみでデータ行がないCSV
  - **エラーケースの概要**: 列定義はあるが実際のデータが存在しない状態

- **入力値**: `'name,age,city'` (ヘッダー行のみ)
  - **不正な理由**: スタイルマップに必要な実データが存在しない
  - **実際の発生シナリオ**: テンプレートファイルや不完全なエクスポート
- **期待される結果**: `throw new Error('No data rows found')`
  - **エラーメッセージの内容**: データ不足の具体的な理由を明示
  - **システムの安全性**: 無効なテーブルの生成を防止
- **テストの目的**: データ整合性チェック機能の確認
  - **品質保証の観点**: Styler生成時のエラー防止
- 🟢 既存統合テストで実装済み、データ検証仕様と一致

#### **ネットワークエラー**

- **テスト名**: URLダウンロード時のHTTPエラー処理
  - **エラーケースの概要**: 存在しないURLやアクセス不能なリソース

  - **不正な理由**: 指定されたURLにリソースが存在しない
  - **実際の発生シナリオ**: URLの入力間違い、外部サービスの障害
- **期待される結果**: `throw new Error('Failed to download: 404 Not Found')`
  - **エラーメッセージの内容**: HTTPステータスを含む具体的なエラー情報
  - **システムの安全性**: ネットワークエラーで処理が中断されても安全
- **テストの目的**: 外部リソースアクセスのエラーハンドリング確認
  - **品質保証の観点**: ネットワーク依存機能の堅牢性確保
- 🟢 既存テストファイルで実装済み、ネットワークエラー仕様と一致

#### **データ整合性エラー**

- **テスト名**: 存在しないテーブルIDでのフィルタリング要求
  - **エラーケースの概要**: 無効なテーブルIDを使った操作の試行

  - **不正な理由**: 指定されたテーブルIDがシステム内に存在しない
  - **実際の発生シナリオ**: テーブル削除後の古い参照、IDの入力間違い
- **期待される結果**: `throw new Error('Table not found')`
  - **エラーメッセージの内容**: 問題の原因を明確に示すメッセージ
  - **システムの安全性**: 不正なデータアクセスを防止
- **テストの目的**: データ参照整合性の確認
  - **品質保証の観点**: データアクセスの安全性保障
