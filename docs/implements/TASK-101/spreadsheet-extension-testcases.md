# テストケース定義: TASK-101 Spreadsheet拡張定義

## 概要
- **タスクID**: TASK-101
- **機能名**: Spreadsheet拡張定義の実装
- **テスト対象**: folderプラグインを拡張するSpreadsheetプラグインの定義
- **作成日**: 2024-12-26

## 開発環境
- **言語**: TypeScript
- **テストフレームワーク**: Vitest
- **関連ライブラリ**: fake-indexeddb, @hierarchidb/common-core

## テストケース一覧

### 1. 正常系テストケース

#### TC-101-001: 拡張定義の基本構造検証
- **テスト名**: Spreadsheet拡張定義が正しい構造を持つことを確認
- **入力値**: SpreadsheetExtensionオブジェクト
- **期待される結果**: 
  - extends: 'folder'
  - nodeType: 'spreadsheet'
  - extendedSteps配列が存在
  - extendedFields配列が存在
- **信頼性レベル**: 🟢 ドキュメントに基づく

#### TC-101-002: Step定義の検証
- **テスト名**: DataSourceStepとFilteringStepが正しく定義されていることを確認
- **入力値**: SpreadsheetExtension.extendedSteps
- **期待される結果**:
  - Step 2: stepNumber=2, title='データソース選択'
  - Step 3: stepNumber=3, title='フィルタリング', dependsOn=[2]
- **信頼性レベル**: 🟢 仕様書に基づく

#### TC-101-003: 拡張フィールド定義の検証
- **テスト名**: Spreadsheet固有フィールドが正しく定義されていることを確認
- **入力値**: SpreadsheetExtension.extendedFields
- **期待される結果**:
  - spreadsheetMetadataIdフィールド（type: 'string'）
  - dataSourceフィールド（type: 'object', required: true）
  - filtersフィールド（type: 'object', required: false）
- **信頼性レベル**: 🟢 設計文書に基づく

#### TC-101-004: バリデーションルールの動作確認（ファイル形式）
- **テスト名**: CSVファイルのバリデーションが正しく動作することを確認
- **入力値**: { dataSource: { type: 'file' }, file: { name: 'data.csv' } }
- **期待される結果**: バリデーション成功（true）
- **信頼性レベル**: 🟢 実装要件に基づく

### 2. 異常系テストケース

#### TC-101-005: 無効なファイル形式の拒否
- **テスト名**: 非対応ファイル形式が適切に拒否されることを確認
- **入力値**: { dataSource: { type: 'file' }, file: { name: 'document.pdf' } }
- **期待される結果**: 
  - バリデーション失敗（false）
  - エラーメッセージ: 'CSV、TSV、またはExcelファイルを選択してください'
- **信頼性レベル**: 🟢 バリデーション仕様に基づく

#### TC-101-006: 必須フィールド未設定エラー
- **テスト名**: dataSourceが未設定の場合のエラーハンドリング
- **入力値**: { name: 'test', description: 'test' }（dataSource欠落）
- **期待される結果**:
  - バリデーション失敗
  - エラー: 'データソースを選択してください'
- **信頼性レベル**: 🟢 スキーマ定義に基づく

#### TC-101-007: ステップ依存関係違反エラー
- **テスト名**: Step3がStep2完了前に実行できないことを確認
- **入力値**: Step3実行試行（Step2未完了）
- **期待される結果**:
  - ステップ実行拒否
  - エラー: 'データソース選択を先に完了してください'
- **信頼性レベル**: 🟡 一般的なステップ制御から推測

### 3. 境界値テストケース

#### TC-101-008: 空のフィルタ配列の処理
- **テスト名**: フィルタが空配列の場合の正常動作確認
- **入力値**: { filters: { rows: [], columns: [] } }
- **期待される結果**:
  - バリデーション成功
  - フィルタなしとして処理
- **信頼性レベル**: 🟢 オプションフィールド仕様に基づく

#### TC-101-009: 最大文字数の境界値テスト
- **テスト名**: name/descriptionフィールドの最大文字数境界
- **入力値**: { name: 'a'.repeat(255), description: 'b'.repeat(1000) }
- **期待される結果**:
  - 255文字まで正常保存
  - 256文字以上でエラーまたはトリミング
- **信頼性レベル**: 🟡 一般的なDB制限から推測

#### TC-101-010: null/undefined値の処理
- **テスト名**: オプションフィールドのnull/undefined処理
- **入力値**: { filters: null, description: undefined }
- **期待される結果**:
  - オプションフィールドは正常処理
  - 必須フィールドはエラー
- **信頼性レベル**: 🟢 TypeScript型定義に基づく

### テスト独立性の確保
- 各テストは独立して実行可能に
- beforeEach/afterEachで環境初期化
- テスト間の依存関係を排除
